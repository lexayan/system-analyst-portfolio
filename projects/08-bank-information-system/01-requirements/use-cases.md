# Описание вариантов использования

Пять вариантов использования; в основном потоке выбраны сценарии кредитного менеджера и CRUDL для учётной записи. См. [диаграмму вариантов использования](../02-diagrams/06-use-case.jpg).

## UC-1. Просмотреть список кредитных заявок

| Поле | Содержание |
|---|---|
| Идентификатор | UC-1 Просмотреть список кредитных заявок |
| Основное действующее лицо | Кредитный менеджер |
| Дополнительные действующие лица | – |
| Описание | Вариант использования позволяет сотруднику просматривать таблицу всех активных кредитных заявок, поступивших от клиентов. |
| Триггер | Менеджер начинает работу или хочет взять в обработку новую заявку. |
| Предварительные условия | PRE-1. Пользователь аутентифицирован. <br> PRE-2. Пользователь обладает правами кредитного менеджера. |
| Выходные условия | POST-1. Отображен список заявок. <br> POST-2. Пользователь может начать рассмотрение конкретной заявки. <br> POST-3. Список пуст, отображено сообщение. |
| Нормальное направление развития варианта использования | 1.0 Просмотреть список заявок <br> 1 Пользователь открывает раздел меню «Кредитные заявки». <br> 2 Система извлекает данные из БД, отображает панель фильтрации и список заявок с колонками: номер заявки, дата создания, ФИО клиента, запрашиваемая сумма, текущий статус. |
| Альтернативное направление развития варианта использования | 1.1 Применение фильтрации <br> 1 На шаге 2 нормального направления пользователь задает параметры фильтра: статус заявки и сумма от/до. <br> 2 Пользователь нажимает «Применить». <br> 3 Система отображает отфильтрованный список заявок. <br> 1.2 Переход к рассмотрению <br> 1 Пользователь нажимает на строку конкретной заявки в статусе «Новая». <br> 2 Система запускает расширяющий процесс «Рассмотреть кредитную заявку». |
| Исключения | 1.0.E1 Ошибка базы данных <br> Система временно недоступна. Система выводит сообщение: «Не удалось загрузить список заявок. Повторите попытку позже». |

## UC-2. Создать учётную запись пользователя

| Поле | Содержание |
|---|---|
| Идентификатор | UC-2 Создать учетную запись пользователя |
| Основное <br> действующее лицо | Системный администратор |
| Дополнительные <br> действующие лица | – |
| Описание | Позволяет зарегистрировать в системе нового сотрудника или клиента. |
| Триггер | Поступила заявка на предоставление доступа новому лицу. |
| Предварительные <br> условия | PRE-1. Администратор находится на экране базового процесса «Просмотреть список учетных записей пользователей». |
| Выходные условия | POST-1. Новая учетная запись создана и сохранена. <br> POST-2. Администратор возвращен к обновленному списку. <br> POST-3. Запись не создана, процесс отменен. |
| Нормальное направление развития варианта использования | 2.0 Создать учетную запись <br> 1 Администратор нажимает кнопку «Добавить пользователя» над списком. <br> 2 Система отображает форму создания учетной записи с полями: ФИО, логин, пароль, роль. <br> 3 Администратор заполняет обязательные поля. <br> 4 Администратор нажимает «Сохранить». <br> 5 Система проверяет корректность данных и уникальность логина. <br> 6 Система сохраняет новую запись, закрывает форму, обновляет список и выводит сообщение об успехе. |
| Альтернативное направление развития варианта использования | 2.1 Отмена создания <br> 1 На шаге 3 или 4 нормального направления администратор нажимает кнопку «Отмена». <br> 2 Система закрывает форму без сохранения введенных данных. <br> 3 Система возвращает администратора к текущему списку пользователей. Вариант использования завершается с результатом POST-3. |
| Исключения | 2.0.E1 Логин уже существует <br> На шаге 5 выясняется, что введенный логин занят. Система отображает сообщение: «Пользователь с таким логином уже существует». Запись не создается, форма остается открытой. |

## UC-3. Просмотреть учётную запись пользователя

| Поле | Содержание |
|---|---|
| Идентификатор | UC-3 Просмотреть учетную запись пользователя |
| Основное действующее лицо | Системный администратор |
| Дополнительные <br> действующие лица | – |
| Описание | Просмотр детальной информации о конкретном пользователе системы. |
| Триггер | Необходимо уточнить данные пользователя или проверить его права. |
| Предварительные <br> условия | PRE-1. Администратор находится на экране «Просмотреть список учетных записей пользователей». |
| Выходные условия | POST-1. Отображена подробная информация о пользователе в режиме чтения. <br> POST-2. Информация не отображена по причине отсутствия записи. |
| Нормальное <br> направление развития <br> варианта <br> использования | 3.0 Просмотреть учетную запись <br> 1 Администратор в списке пользователей нажимает на нужную запись. <br> 2 Система открывает карточку пользователя с недоступными для редактирования полями: ФИО, логин, роль, дата регистрации, текущий статус. <br> 3 Администратор нажимает кнопку «Закрыть» или «Назад». <br> 4 Система возвращает администратора на экран списка. |
| Альтернативное направление развития варианта использования | 3.1 Переход к редактированию <br> 1 На шаге 3 нормального направления администратор нажимает кнопку «Редактировать» внутри карточки. <br> 2 Система немедленно запускает процесс UC-4, переводя поля в режим редактирования. |
| Исключения | 3.0.E1 Запись удалена <br> На шаге 1 нормального направления выясняется, что другой администратор уже удалил пользователя. Система отображает сообщение об ошибке и обновляет список. Вариант использования завершается с результатом POST-2. |

## UC-4. Изменить учётную запись пользователя

| Поле | Содержание |
|---|---|
| Идентификатор | UC-4 Изменить учетную запись пользователя |
| Основное действующее лицо | Системный администратор |
| Дополнительные <br> действующие лица | – |
| Описание | Редактирование личных данных пользователя или смена его роли. |
| Триггер | Сотрудник переведен на другую должность или изменились его персональные данные. |
| Предварительные <br> условия | PRE-1. Администратор находится на экране «Просмотреть список учетных записей пользователей». |
| Выходные условия | POST-1. Изменения в учетной записи сохранены в БД. <br> POST-2. Изменения не сохранены. |
| Нормальное <br> направление развития <br> варианта <br> использования | 4.0 Изменить учетную запись <br> 1 Администратор нажимает на иконку «Редактировать» в строке пользователя. <br> 2 Система отображает форму редактирования, заполненную текущими данными. <br> 3 Администратор изменяет нужные данные. <br> 4 Администратор нажимает кнопку «Сохранить изменения». <br> 5 Система проверяет корректность введенных данных. <br> 6 Система обновляет запись в базе данных и выводит сообщение об успехе. |
| Альтернативное направление развития варианта использования | 4.1 Отмена редактирования <br> 1 На шаге 3 или 4 нормального направления администратор нажимает кнопку «Отмена». <br> 2 Система сбрасывает все несохраненные изменения. <br> 3 Система закрывает форму и возвращает пользователя к списку. Вариант использования завершается с результатом POST-2. |
| Исключения | 4.0.E1 Ошибка валидации <br> Администратор стер обязательное поле. Система выводит предупреждение о пустом поле. Сохранение прерывается. |

## UC-5. Удалить учётную запись пользователя

| Поле | Содержание |
|---|---|
| Идентификатор | UC-5 Удалить учетную запись пользователя |
| Основное <br> действующее лицо | Системный администратор |
| Дополнительные <br> действующие лица | – |
| Описание | Полное удаление или бессрочная блокировка учетной записи пользователя в системе. |
| Триггер | Сотрудник уволился или клиент прекратил обслуживание. |
| Предварительные <br> условия | PRE-1. Администратор находится на экране «Просмотреть список учетных записей пользователей». |
| Выходные условия | POST-1. Учетная запись удалена. <br> POST-2. Удаление отменено администратором или запрещено системой. |
| Нормальное <br> направление развития <br> варианта <br> использования | 5.0 Удалить учетную запись <br> 1 Администратор нажимает иконку «Удалить» в строке нужного пользователя. <br> 2 Система выводит модальное окно с предупреждением о необратимости действия. <br> 3 Администратор нажимает «Удалить». <br> 4 Система проверяет наличие связей пользователя с важными документами. <br> 5 Система удаляет запись, скрывает окно, обновляет таблицу и выводит сообщение об успехе. |
| Альтернативное направление развития варианта использования | 5.1 Отмена действия <br> 1 На шаге 3 нормального направления администратор нажимает «Отмена». <br> 2 Модальное окно закрывается, список остается без изменений. Вариант использования завершается с результатом POST-2. |
| Исключения | 5.0.E1 Попытка удалить самого себя <br> Система определяет, что выбранный аккаунт принадлежит текущему администратору. Система выводит сообщение об ошибке безопасности. Процесс прерывается. |
