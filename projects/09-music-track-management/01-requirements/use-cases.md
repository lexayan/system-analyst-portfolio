# Описание вариантов использования

Пять ключевых сценариев из списка на [диаграмме вариантов использования](../02-diagrams/01-use-case.jpg).

## UC-1. Загрузить трек

### Краткое описание

Вариант использования позволяет пользователю загрузить новый аудиофайл в систему, указав метаданные (название, исполнитель, жанр).

### Основной поток событий

Данный вариант использования начинает выполняться, когда у пользователя возникла потребность добавить новый трек в свою библиотеку.

1. Пользователь открывает раздел «Моя музыка».

2. Система отображает список загруженных треков и действие «Загрузить трек».

3. Пользователь выбирает «Загрузить трек».

4. Система отображает форму с полями: Файл трека (обязательное, mp3/wav, не более 20 Мб), Название (1-100 символов), Исполнитель (по умолчанию «Неизвестный исполнитель»), Жанр (опционально, выбор из списка).

5. Пользователь выбирает файл, заполняет поля и нажимает «Загрузить».

6. Система проверяет формат и размер файла.

7. Система сохраняет файл и метаданные в базе данных.

8. Трек отображается в списке «Моя музыка» пользователя.

### Альтернативные потоки

Неверный формат файла. Если формат файла отличается от допустимых (не *mp3/wav*), система отображает сообщение «Неподдерживаемый формат файла», не сохраняет данные и возвращает пользователя к шагу 5.

Превышен лимит размера. Если файл больше 20 Мб, система отображает сообщение «Файл слишком большой», не сохраняет данные и возвращает пользователя к шагу 5.

Техническая ошибка загрузки. Если при сохранении возникает сетевая или серверная ошибка, система отображает сообщение «Ошибка при загрузке трека, попробуйте позже», данные не сохраняются.

### Предусловия

Пользователь аутентифицирован в системе. У пользователя есть доступ к интернету и аудиофайл на устройстве.

### Постусловия

Трек успешно загружен и сохранен в базе данных. Трек отображается в списке «Моя музыка» пользователя (при ошибке данные не сохраняются).

## UC-2. Обновить трек

### Краткое описание

Вариант использования позволяет пользователю изменить метаданные (название, жанр, исполнитель) ранее загруженного им трека.

### Основной поток событий

Данный вариант использования начинает выполняться, когда пользователь хочет исправить ошибку в названии или сменить жанр трека.

1. Пользователь открывает раздел «Моя музыка».

2. Система отображает список треков.

3. Пользователь выбирает нужный трек и нажимает действие «Редактировать».

4. Система отображает форму с текущими данными трека (аналогично шагу 4 варианта «Загрузить трек»).

5. Пользователь изменяет название, исполнителя или жанр.

6. Пользователь нажимает «Сохранить».

7. Система проверяет корректность введенных данных.

8. Система сохраняет изменения в базе данных.

9. Обновленная информация отображается в списке.

### Альтернативные потоки

Попытка редактирования чужого трека. Если пользователь пытается получить доступ к форме редактирования трека, автором которого он не является, система выдает ошибку «Доступ запрещен».

Техническая ошибка. Если при сохранении возникает ошибка, выводится сообщение: «Произошла техническая ошибка, данные не сохранены».

### Предусловия

Пользователь аутентифицирован в системе. Трек существует в системе и его автором является данный пользователь.

### Постусловия

Метаданные трека обновлены (при возникновении технической ошибки данные не изменены).

## UC-3. Удалить трек

### Краткое описание

Вариант использования позволяет пользователю безвозвратно удалить свой трек из системы.

### Основной поток событий

Данный вариант использования начинает выполняться, когда пользователь решил удалить трек из своей библиотеки.

1. Пользователь открывает раздел «Моя музыка».

2. Система отображает список треков.

3. Пользователь выбирает трек и нажимает действие «Удалить».

4. Система запрашивает подтверждение удаления.

5. Пользователь подтверждает удаление.

6. Система удаляет файл и запись о треке из базы данных.

7. Система обновляет список треков пользователя.

### Альтернативные потоки

Отказ от подтверждения. Если пользователь нажимает «Отмена» на шаге 5, удаление прерывается, трек остается в системе.

### Предусловия

Пользователь аутентифицирован. Пользователь является владельцем (автором загрузки) трека.

### Постусловия

Трек удален из базы данных и файлового хранилища. Трек более не отображается в списках.

## UC-4. Посмотреть список треков

### Краткое описание

Вариант использования позволяет пользователю просматривать общую библиотеку доступных треков или свои загрузки.

### Основной поток событий

Данный вариант использования начинает выполняться, когда пользователь хочет найти музыку для прослушивания.

1. Пользователь переходит в раздел «Библиотека».

2. Система обращается к базе данных.

3. Система отображает список треков с полями: Название, Исполнитель, Продолжительность, Дата загрузки.

4. Пользователь может прокручивать список.

### Альтернативные потоки

Список пуст. Если в базе данных нет доступных треков, система отображает сообщение «В библиотеке пока нет треков».

### Предусловия

Пользователь аутентифицирован.

### Постусловия

Пользователь получил актуальный список треков.

## UC-5. Удалить трек администратором

### Краткое описание

Вариант использования позволяет администратору удалить любой трек из системы в случае нарушения правил (модерация).

### Основной поток событий

Данный вариант использования начинает выполняться, когда поступила жалоба на трек или выявлено нарушение авторских прав.

1. Администратор открывает панель управления («Панель модератора»).

2. Администратор находит трек через поиск или в общем списке.

3. Администратор нажимает действие «Удалить трек».

4. Система запрашивает причину удаления.

5. Администратор выбирает причину из списка (например, «Нарушение авторских прав») и подтверждает действие.

6. Система удаляет трек.

7. Система отправляет автоматическое уведомление пользователю-владельцу.

8. Трек исчезает из общего доступа.

### Альтернативные потоки

Ошибка уведомления. Если трек удален, но уведомление не удалось отправить, администратору выводится предупреждение: «Трек удален, но уведомление автору не доставлено». Сценарий считается завершенным.

### Предусловия

Администратор аутентифицирован с соответствующими правами доступа.

### Постусловия

Трек удален из системы. Автору трека отправлено уведомление о причине удаления.
